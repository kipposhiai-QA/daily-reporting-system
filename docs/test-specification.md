# 営業日報システム テスト仕様書

本書は `docs/requirements.md`、`docs/screen-definitions.md`、`docs/api-specification.md` に基づく機能を検証するためのテスト仕様である。実装はまだ行わない。

## 1. 目的・対象範囲

- 目的：要件定義書・画面定義書・API仕様書で定義した機能・権限・バリデーションが仕様通りに動作することを確認する。
- 対象：
  - 画面テスト（SCR-01〜07、ブラウザ操作レベル）
  - APIテスト（`docs/api-specification.md` の各エンドポイント、結合テストレベル）
- 対象外：フロントエンド/バックエンドの単体テスト（関数・コンポーネント単位）は実装時に開発者が別途作成する前提とし、本書では扱わない。

## 2. テスト環境・前提データ

### 2.1 環境

- テスト用DB（本番と分離）を用いた開発環境、もしくはCI環境。
- 各テストケース実行前に、下記2.2の前提データでDBを初期化した状態からスタートする（テストケース間の依存を避ける）。

### 2.2 共通シードデータ

**SALES_PERSON**

| sales_person_id | name     | department | is_manager |
| --------------- | -------- | ---------- | ---------- |
| 1               | 山田太郎 | 営業1課    | false      |
| 2               | 田中花子 | 営業2課    | false      |
| 5               | 鈴木一郎 | 営業1課    | true       |

**CUSTOMER**

| customer_id | company_name |
| ----------- | ------------ |
| 1           | 株式会社A社  |
| 2           | 株式会社B社  |

**DAILY_REPORT**

| report_id | sales_person_id | report_date | status    | 備考                            |
| --------- | --------------- | ----------- | --------- | ------------------------------- |
| 10        | 1               | 2026-08-25  | SUBMITTED | 訪問記録2件（customer_id=1, 2） |
| 11        | 1               | 2026-08-24  | DRAFT     | 訪問記録なし                    |

上記に加えて、各テストケースで固有に必要なデータは各ケースの「事前条件」に追記する。

### 2.3 凡例

- 「営業としてログイン」＝ `X-Sales-Person-Id: 1`（山田太郎, is_manager=false）を指定 / 画面ではユーザー切替で山田太郎を選択
- 「上長としてログイン」＝ `X-Sales-Person-Id: 5`（鈴木一郎, is_manager=true）を指定 / 画面ではユーザー切替で鈴木一郎を選択
- 「別営業としてログイン」＝ `X-Sales-Person-Id: 2`（田中花子, is_manager=false）

## 5. トレーサビリティ

各テストケースIDは対象の画面ID（SCR-xx）またはAPIエンドポイント（`docs/api-specification.md` 章番号）に対応しており、要件定義書の該当節（3.1〜3.4）に遡って確認できる。実装時・改修時は、関連する要件・画面・APIの変更に応じて本書のテストケースも合わせて見直すこと。
