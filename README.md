# 営業日報システム (daily-reporting-system)

営業担当者の日報作成・訪問記録管理・顧客管理を行う社内向けWebアプリケーションです。

## 🤖 開発体制について

**本プロジェクトは、原則として要件定義・設計・レビュー・QA設計を私が担当し、実装およびテストコードの作成はAI(Claude Code)が行っています。**

- Issue(要件)の作成、仕様レビュー、QA視点でのテスト設計・不具合検出は私が担当
- コーディング・テストコード実装・CI/CD構築はClaude Codeに指示して実施
- プルリクエストのレビュー、動作確認、本番環境での品質確認は私が実施

この開発スタイルにより、AIを活用した高速な開発サイクルと、QAエンジニアとしての品質担保・要件整理の両方を提供できます。ご依頼いただく際は、この開発体制を前提にご検討ください。

## 主な機能

- 日報の作成・編集・詳細表示
- 顧客マスタ管理(登録・編集・検索)
- 営業担当者マスタ管理(登録・編集、上長権限)
- コメント機能(上長からのフィードバック)
- 認証・権限管理(一般担当者/上長)

## 技術構成

| 分類           | 技術                                                      |
| -------------- | --------------------------------------------------------- |
| フロントエンド | Next.js (App Router), TypeScript, Tailwind CSS, shadcn/ui |
| バックエンド   | Next.js API Routes, Prisma                                |
| データベース   | Supabase (PostgreSQL)                                     |
| 認証           | Supabase Auth                                             |
| テスト         | Vitest (単体・結合), Playwright (E2E)                     |
| CI/CD          | GitHub Actions                                            |
| インフラ       | Google Cloud Run                                          |

## テスト・品質への取り組み

QAエンジニアとしての経験を活かし、以下の品質担保プロセスを実践しています。

- **テストケース仕様書**によるケースID管理(画面テスト・APIテストあわせて200件超)
- 画面テスト(Vitest + Testing Library)、API結合テスト(実DB接続)、E2Eテスト(Playwright)の3層構成
- QAテスト設計の観点での不具合検出・修正(例: 権限昇格の脆弱性発見・修正、異常系テストの追加)
- pre-pushフックによるテスト自動実行(失敗時はpush不可)
